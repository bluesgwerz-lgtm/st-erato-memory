# Erato Memory

为 Erato 预设定制的 SillyTavern 长期记忆扩展。手机 / 电脑双端可用。

- 按**段**总结：攒够 N 楼（默认 20）自动把这一段交给副 API 一次总结，按事件切成记忆条目（一场争吵、一次亲密不再拆成十条），一次调用最多吃 W 楼（默认 40，可开到 200）。楼数按酒馆楼层计：你一条 + AI 一条 = 2 楼
- 同一次调用先**点名**再写事件：本段出现过的每个人（包括只被提到、没到场的主角亲属）都进点名表，按对剧情的影响分主/配/龙套，带性别；再顺手维护**人物志 / 物件 / 主角现状**：身份、性别、年龄（原文有依据才写）、对 {{user}} 的称呼、与双方的关系、立场、生命周期状态（在场/离场/死亡/下落不明）、现状、知情范围（只累加不覆盖）、此刻所处阶段、对他人的看法与趋势；物件分关键/次要/摆设，带状态（待用/在用/已使用/已转手/遗失/损毁/封存）和持有者
- **主角现状**：{{user}} 与 {{char}} 不进人物志，只记「之后所有场景都会沿用」的长期变化——职业身份、住处、身体、婚姻家庭，{{char}} 多一项「已经知道了 {{user}} 的什么」；两人关系一行 = 形态（同事/恋人/同居/已婚，含明言的约定）+ {{char}} 对 {{user}} 的态度。这些是随剧情变了、而人设卡上还是旧值的东西：注入时标明「列出的项比人设卡更新，没列的仍按卡」，不整体压卡。当天在哪、穿什么、心情不记
- 副 AI 报回的名字带尾部括注（「杨晚星（星星/晚星妹妹）」）时剥成名字 + 别称再匹配，不会把同一人分成两档；喂给副 AI 的档案行名字单独在行首、别称在行尾
- 性别只写一次不覆盖（性别不随剧情变），称呼以最新为准（副 AI 只在原文明确改口时才写新值）；档案里的性别与副 AI 新报的相反时不合并、卡上标「⚠性别冲突」，防两个同名人物被悄悄合成一个。人物久未露面时注入块的一行名单也带性别，召回后不再猜他/她
- 档位只升不降（某段只露一面不会被降档），面板手改后锁定；龙套进过 S/A 事件或累计露面 ≥3 段自动升配；你手改过档位的人只按手改之后的露面重新计数
- 与 Erato 的恒定窗口正则组严格对齐：正文被窗口剥离之后，由记忆条目接管
- 总结完成后自动隐藏已总结的旧楼层，只保留最近 N 楼可见（可逆，默认开），长聊天在手机上不再卡
- S/A/B/C 四级记忆 + 手动钉选，按楼层衰减；人物志按「最近几楼提到谁」决定谁出完整档案；龙套与摆设不进提示词，已使用/遗失/损毁/封存的物件只留一行「已了结」
- 副 API 拒答、输出损坏、事件给得太少（过度压缩）时自动把段落对半拆分重试；输出被截断先带长度约束重来一次；限流（429）、上游 5xx、网络错、超时、空回复这类暂时性失败在同一批次内退避重试两次（3 秒、8 秒），鉴权/参数错直接失败不重发。最近八次原始回复留在面板里可查、可导出 .txt，失败的调用也留一行错误记录
- **三层压缩，长聊不失忆**：往事超出注入上限时先裁最老最轻的 B/C，被裁的条目攒够后由副 API 按故事日折成一行「远景」骨架（非破坏，条目仍在库里），远景超预算再把最老的日行折成时期行；S 永不裁，超过阈值压成一段正典。折叠只压措辞不删人名、日期、物件、承诺、结果
- **楼楼有记录**：每楼自带的作者摘要（recap）存成底层，未总结/失败/副模型申报无事的楼在提示词里用它保底；副模型跳过的楼会被点名要求补写，输出末尾的结束标记缺失即视为截断重来
- **召回**：关键词召回默认开、零网络，把被裁掉/已折叠的条目按当下话题捞回来；可选向量召回（高楼层用）走酒馆自带向量接口，地址 + 密钥 + 拉取模型选一个，任何 OpenAI 兼容 embeddings 接口都行，服务端存储，另把已总结楼层的正文切块入库捞「摘要没写进的小细节」；用户消息一发出就预取，生成前最多等 4 秒
- 钉选与手改过的记忆重跑本段时保留；删掉的人物/物件不会被副 AI 复活（可恢复）；手改过的档案字段、看法、主角现状副 AI 不再覆盖
- **删楼能回滚**：删掉已总结的楼层后，该段记忆过期重跑，档案里来自这些楼的值退回上一版（每个值留最近三版历史），涉及的远景行作废重折，含被删 S 的正典立即重压；条目卡上的「撤销本段」对「AI 总结得不对」做同样的整段回退
- 记忆随聊天文件保存；两端连同一个酒馆实例时自动共享
- 手机优先：半透明可拖动的悬浮球（角标显示待总结楼数）+ 魔杖菜单入口；面板单列，一键「总结到当前」跑到底

## 安装

酒馆 → 扩展面板 → 安装扩展 → 填入本仓库地址：

```
https://github.com/bluesgwerz-lgtm/st-erato-memory
```

## 使用

1. 打开面板：点屏幕上的羽毛笔悬浮球（可拖动，松手吸边），或输入框左侧魔杖菜单里的「记忆面板」。首次未配 API 会直接落到设置页。
2. 填副 API 地址（如 `https://api.example.com/v1`）和密钥，点「拉取模型」选模型；接口不支持列模型时在「模型名」里手填。点「测试连接」确认可用。
3. 设置页「总结节奏」：
   - **自动总结**：手动 / 每 20 / 30 / 40 楼 / 自定义。攒够这么多新楼就自动总结一次；选「手动」则只在点按钮时总结。
   - **单次总结最大楼层**：40 / 60 / 100 / 200 / 自定义。一次副 API 调用最多吃多少楼。越大越省钱也越粗：日常 40–60，清不在乎细节的老积压再开到 100–200。
   - 以上楼数都按酒馆楼层计（你一条 + AI 一条 = 2 楼），面板上「已总结 / 待总结 N 楼」也是同一口径，和聊天里的楼号对得上。
   - **单次最大字数**（默认 6 万字）：材料超过这个数自动再切一段，按副模型的上下文大小调。
   - **事件密度**（默认每 4 个 AI 楼 ≥ 1 条）：副模型把一大段压成两三条时视为过度压缩，自动拆半重跑。设 0 关闭。
4. 旧聊天：面板顶部会显示「待总结 N 楼」，点「总结到当前」，确认框会报大约几次调用，然后一次跑到底（可中途停止，带进度）。魔杖菜单里的「总结到当前」不开面板也能跑。
5. 新聊天：正常聊即可，攒够设定楼数后自动总结（最新两楼留着，等它们沉下去再入库）。点「总结到当前」则连最新楼一起总结。
6. 总结完成后，除最近 6 楼外的已总结楼层会被隐藏（酒馆的「隐藏消息」，仍可在聊天里看到，只是不进提示词）。「更多 → 取消隐藏」可一键恢复；设置里可关掉或改保留楼数。
7. 「人物志」分区顶部是**主角现状**：「两人关系」（形态：同事/恋人/同居/已婚…，含明言的约定）和「{{char}} 对 {{user}} 的态度」两行可直接改，改过即锁；下面钉着 {{user}} 与 {{char}} 两张卡，只有职业身份 / 住处 / 身体 / 婚姻家庭（{{char}} 多一项「知情」）四五个键，点卡展开可改，改过的字段带 🔒，点 🔒 即解锁这一项。副 AI 只在剧情里发生了长期改变时才写这几项，没变就空着。再往下是配角人物志：筛选条可按档位（主/配/龙套）、状态（在场/离场/死亡/下落不明）、活跃度（近期 = 最近几楼提到、也就是本轮出完整卡的人；沉寂 = 100 楼没露面）筛，可搜名字/别称/身份，可按最近露面/首见/名字/露面段数排。点卡展开可改名字、别称、档位、状态、各字段（性别是下拉）、对他人的看法，或删除；档位和状态手改后锁定（🔒），副 AI 不再覆盖，点 🔒 即解锁；卡头的「🔒N」是这张卡的锁数，点一下确认后整卡全解（值不动）。「知情」字段只累加不覆盖（知道了就不会变回不知道），最多留 10 条。卡上出现「⚠性别冲突」= 副 AI 在某一楼把此人报成了相反性别，那一段对此人的更新没有并进来：若是副 AI 认错，保存本卡即清除；若真是两个同名的人，改名字或别称区分开。值旁边的 `#楼层` 可点跳过去核对。老聊天人物志不全时，「更多 → 从事件补人物」零网络把事件里点到的人先建档，下次总结自动补全字段。
8. 「物件」分区：按关键性（关键/次要/摆设）、状态（待用/在用/已使用/已转手/遗失/损毁/封存，或「已了结」合并筛）、持有者筛，可搜名字/持有者/备注/意义。摆设只留在面板不进提示词；已使用/遗失/损毁/封存的物件在提示词里只占一行「已了结」。
9. 时间线里：点等级块循环改等级，长按钉为 S 级；点卡片展开可编辑、重跑本段、跳到该楼。失败/拒答的段落显示在时间线顶部，可重试、拆半重试或标为不入库。「更多 → 手动新增」可补录遗漏的事。
10. 「本轮注入预览」分区能直接看到这轮塞给模型的记忆原文，不用开提示词查看器；「副 API 最近的原始回复」分区留着最近八次调用的原文（每条带时间、窗口、模型、finish 与「压缩重试 / 纠正重试：原因」标注），摘要不对劲或调用次数比预期多时先看这里。「导出原始回复 (.txt)」把这几条存成文本文件方便发出去看；排查前先点「清空记录」，再总结一次，导出来的就只有这一次的调用。
11. 「远景 · 正典」分区：看被折叠出来的按日/按时期骨架（可改可删，改过的行带 🔒 之后不会被折叠覆盖，行里「解锁」恢复自动折叠）和正典压缩段（点击可编辑，改了才锁定，「解锁」或「重建正典」恢复重压）；「现在折叠」立刻跑一次折叠与正典压缩。设置「长期记忆」组可调正典阈值、远景预算、攒几条再折叠、recap 保底深度（与预设 5🌸 的 minDepth 一致，默认 20），以及自动整理的时机（默认只在总结批次结束后跑；可改成每次生成后攒够就跑，或只手动）。自动整理跑完会弹一次提示。
12. 设置里副 API 正下方是「向量召回（高楼层可选）」，两三百楼以内不用开。要开：填 embeddings 接口的地址和密钥（填法和副 API 一样，任何 OpenAI 兼容接口都行，硅基流动填 `https://api.siliconflow.cn/v1`），点「拉取向量模型」在下拉框里选一个（像 embedding 的排在前面，硅基流动选 `Qwen/Qwen3-Embedding-0.6B` 或 `BAAI/bge-m3`），勾「启用向量召回」，点「测试向量连接」；老聊天点「补向量」灌一次。密钥会自动写进酒馆的向量密钥槽位，不用手动操作。之后新总结的段落自动入库；「重建向量」清空重灌。原文细节默认开（已总结楼层的正文切块入库，会发给向量服务）。关键词召回不需要任何配置，默认开。
13. **锁的规则**：只有真改过的内容才上锁——点开卡片看看再保存，什么都不会锁，提示会写「没有改动」或「锁定 N 项」。时间线卡片改过标题/摘要/等级后带 🔒，重跑本段时保留，可点「解锁」；「撤销本段」把这一段的总结整个退掉（删记忆、档案退回上一版、远景作废、楼层恢复显示），楼层不动，之后可重新总结。人物志/物件的档位、状态、字段、看法改过都带 🔒，**点 🔒 就解锁这一项**（逐项解，不影响同卡其他锁）；每张人物/物件卡卡头有「🔒N」（N=这张卡上的锁数），**点它一键解除整卡所有锁**，值不动；主角现状的字段仍逐项点 🔒 解。手改过档位的人，之后自动升配只认手改之后的露面（重新攒 3 段或进一次 S/A 事件），解锁不会被旧账瞬间升回去；手改值的来源楼层被删时带「?」待核；首见楼与所有来源楼都被删的人物/物件标「来源全失」，不注入，再被提到或手动保存即恢复。删掉的人物/物件在分区底部「已删除」里，点名字恢复。
14. 删掉已总结的楼层后：该段记忆自动过期，自动模式下一次收到消息就重跑（手动模式会提醒你点「总结到当前」）；重跑完成前，这段楼层在提示词里由作者摘要保底，不会出现空白。「本轮注入预览」顶部有各段字数，调预算时看它。设置「提示词」组可改注入块块首说明。
15. **换个窗口接着这条线**：「更多 → 导出前史文本 (.txt)」把本聊天的记忆整理成一段纯文本（也会尽量复制进剪贴板），贴进**新聊天的世界书**里当前史。它不是迁移：贴出去的是冻结快照，新聊天里插件会另起一份档案，所以文本里只保留不会过时的东西——远景、正典与 A 级要点照搬（已折进远景的不重复，B 级不进），人物只留身份/性别/称呼/关系/外貌/立场/知情/看法（在场离场、现状、阶段这些会过时的不写，死亡保留；只有名字和身份的人合成一行「其他已登场」），物件只留持有者与意义（临时状态、「叠在箱中」这类备注、楼号履历都不进），主角现状整块标「截至前史结束时」，开头一行写明「现在的状态以对话里最新描述为准」。建议贴进按聊天绑定的「聊天世界书」或新建一张卡，别贴进角色世界书（会带到这个角色的所有聊天）；顺序：总结到当前 → 等整理跑完 → 导出 → 新聊天贴。「导入 JSON」只对同一聊天的备份恢复与分支有效，换聊天导入会因为楼号对不上全部作废。

斜杠命令（可接进 QuickReply）：`/em-panel` 开面板 · `/em-summarize` 总结到当前 · `/em-pin 楼层号` 钉/取消钉该楼所在的记忆 · `/em-note 文字` 手动记一条。

## 与预设的配合

- 「正文窗口」设置默认 6，与预设正则 `6🌸发送最后4层正文` 的 minDepth 一致；两边改要一起改。开着「隐藏已总结」时，可见楼层通常都在窗口内，记忆块落在它们前面。
- 副 API 的选择决定 NSFW 楼层能否入库；拒答会先自动拆半重试，仍失败的段落在面板顶部红条显示，可换模型后「更多 → 重试失败」。
- 副 API 的「回复上限」默认 4000 token：一段最多 40 楼（20 个回合）会产出十来条事件加档案，太小会截断（截断会触发拆半）。
- 提示词模板可在设置「提示词」组里查看并修改（留空即默认；必须含 `{{material}}`）。

## 用其他预设

能用，但摘要材料的干净程度取决于你的预设和 Erato 撞不撞标签。插件默认只取 `<content>…</content>` 里的正文；找不到这对标签时，把整楼减去 `think / thinking / think_format / COT_Director`、`<details>`、`<recap>`、`<plot_directions>`、道具卡后当正文。你的预设如果用别的思考标签（`<thought>`、`<reasoning>`……）或状态栏写法，它们会原样进摘要材料——思考里的备选走向、状态栏里的数值会被当成事件记下来。

设置「正文提取」组一个勾选、两个框解决这件事：
- **本聊天启用自定义提取**：按聊天记。用别家预设的聊天勾上，Erato 聊天不勾。两个正则框的内容是全局保存的，换回 Erato 聊天不用清空，没勾的聊天一律走 Erato 默认。
- **正文提取正则**：你的预设有自己的正文标签就填，捕获组 1 当正文（如 `<body>([\s\S]*?)</body>`）；没有正文标签就留空。
- **额外剥除正则**：一行一条，取正文前先从整楼剥掉，填你预设的思考块、状态栏标签（如 `<thought>[\s\S]*?</thought>`）。

新聊天先勾、填好再总结。已经总结过再勾或再改正则，本聊天所有段落会被判为「过期」，下次总结时重跑。没有 `<recap>` 的预设，故事时间由副 AI 从正文推断，推不出留空。
